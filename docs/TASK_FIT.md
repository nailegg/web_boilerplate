# 과제 적합성 판단

## 이 기반이 적합한 경우

다음 조건이 하나 이상 있으면 이 저장소를 기반으로 시작할 수 있다.

- 로그인 사용자가 있는 웹서비스
- 역할에 따른 화면 또는 API 접근 제어
- 데이터 저장과 조회가 필요한 서비스
- 생성·수정·삭제 또는 상태 변경 흐름
- 시간이 걸리는 계산, 파일 처리, 외부 요청
- 짧은 시간 안에 브라우저에서 확인 가능한 MVP가 필요한 과제

## 사용하지 않는 경우

다음 중 하나라도 해당하면 clone하지 않는다. 필요하면 `lib/auth`의 패턴만 참고한다.

- 과제가 스타터 코드, 언어, 프레임워크를 지정함 (예: 제공된 Python/FastAPI 프로젝트)
- 기존 코드 수리나 실패 테스트 통과가 과제임
- 산출물이 화면이 아니라 결과 파일, CLI, 보고서, 노트북임
- Node.js 20 이상이 없거나 npm 레지스트리에 접근할 수 없음

## 먼저 구조를 바꿔야 하는 경우

다음 조건이 핵심이면 기본 구조를 그대로 사용하지 말고 필요한 부분만 가져온다.

- 인증이 전혀 필요 없는 공개 페이지
- 실시간 협업이나 매우 높은 동시성이 핵심
- 대용량 파일 처리나 스트리밍이 중심
- 외부 인증·결제·메시지 시스템이 필수
- 여러 조직과 복잡한 조직별 권한이 핵심
- 처음부터 여러 웹 서버와 여러 Worker를 운영해야 함

## 시작 전에 결정할 네 가지

| 구분 | 결정할 내용 |
|---|---|
| 사용자 | 로그인하는 주체와 익명 사용자의 범위 |
| 권한 | 역할별로 볼 수 있고 변경할 수 있는 기능 |
| 데이터 | 저장해야 하는 핵심 리소스와 관계 |
| 흐름 | 사용자가 처음부터 끝까지 수행하는 최소 업무 흐름 |

이 네 가지가 정해지면 그에 맞는 모델, API, 화면만 추가한다. 기본 예제의 모델명이나 화면을 제품 요구사항으로 해석하지 않는다.
